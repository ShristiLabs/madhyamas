# Project Conventions

Shared conventions for the Madhyamas codebase. Load this reference before making
code changes so output matches existing patterns.

## Repository Layout

```
madhyamas/
├── crates/
│   ├── madhyamas/             # Unified binary (subcommands: serve/mcp/cli)
│   ├── madhyamas-core/        # Proxy engine, TLS, traffic store, intercept, plugins
│   ├── madhyamas-api/         # axum REST/WebSocket API + embedded web assets
│   ├── madhyamas-cli/         # CLI library (re-exported by main binary)
│   ├── madhyamas-mcp/         # MCP server library (re-exported by main binary)
│   └── madhyamas-plugin-sdk/  # Guest SDK for WASM plugins
├── web/                       # React + TypeScript frontend (Vite, Tailwind, shadcn/ui)
├── docs/                      # Developer / reference documentation
├── docs-site/                 # End-user documentation (VitePress)
├── plugins/                   # Bundled example plugins + registry.json
├── skills/                    # Published AI skill package (@madhyamas/skill)
├── agents/                    # THIS directory — specialized AI agent definitions
├── docker/                    # Docker setup
└── Cargo.toml                 # Workspace manifest
```

## Backend (Rust)

- **Workspace**: 6 crates under `crates/`. The unified `madhyamas` binary re-exports
  core/api/cli/mcp via subcommands.
- **Async runtime**: `tokio`. Use `tokio::spawn` for fire-and-forget, `tokio::time::interval`
  for periodic tasks.
- **HTTP stack**: `hyper` + `axum` (API) + `rustls` (TLS). Never use `reqwest` for the
  proxy path — use `hyper` directly.
- **Storage**: `rusqlite` (SQLite). Persist new state via the existing `TrafficStore`
  patterns; never invent a second database connection per request.
- **Embedding**: `rust-embed` serves the compiled `web/dist` from inside the binary.
  Frontend must be built (`cd web && npm run build`) BEFORE `cargo build`.
- **Error handling**: `thiserror` for library error enums, `Result<T, E>` everywhere.
  Avoid `unwrap()`/`expect()` in production paths; prefer `?` with context.
- **Logging**: `tracing` crate. Use `tracing::info!`/`debug!`/`warn!`/`error!` — never `println!`.
- **CLI parsing**: `clap` derive macros.
- **Serialization**: `serde` + `serde_json`. All API types derive `Serialize`/`Deserialize`.

### Build / verify commands

```bash
cargo build --release -p madhyamas        # Build unified binary
cargo fmt --all                            # Format
cargo clippy --all-targets --all-features  # Lint (must be clean)
cargo test                                 # Run tests
RUST_LOG=debug cargo run --bin madhyamas   # Run with debug logs
```

### Adding a new crate feature

1. Add the module under the appropriate crate (`core` for proxy logic, `api` for HTTP endpoints).
2. Export from the crate's `lib.rs`.
3. If user-facing, add a CLI subcommand (`madhyamas-cli/src/commands/<name>.rs`) and wire it into `Commands` enum.
4. If AI-agent-facing, add an MCP tool (`madhyamas-mcp/src/tools/<name>.rs`) and register it.
5. If config-bearing, extend the `Config` struct and persist via SQLite.
6. Document in `docs/` (developer reference) and `docs-site/` (end-user guide).

## Frontend (web/)

- **Stack**: React 18, TypeScript, Vite, Tailwind CSS, shadcn/ui, TanStack Query, Zustand.
- **Build**: `cd web && npm run build` (must run before Rust build — assets are embedded).
- **Dev**: `cd web && npm run dev`.
- **State**: Zustand stores in `src/store/`. TanStack Query for server state.
- **API client**: `src/api/` — typed fetch wrappers matching `madhyamas-api` routes.
- **Components**: shadcn/ui primitives in `src/components/ui/`; feature components alongside their panels.
- **No emojis** in UI strings or comments.

## Documentation

- `docs/` — developer-facing reference (ARCHITECTURE.md, API.md, PLUGIN_*.md, etc.).
  Markdown only. Filename `UPPER_SNAKE_CASE.md` for top-level feature docs.
- `docs-site/` — end-user guide (VitePress). See `references/docs-site-structure.md`.
- Every new feature MUST get a `docs/` entry. End-user docs are added when the feature
  is user-visible.

## Git

- Conventional commit style is acceptable but not enforced; match surrounding history.
- Never commit secrets, certificates, or `target/` artifacts.
- `AGENTS.md` (canonical project instructions) and `agents/` are committed; harness-specific output dirs (`.devin/`,
  `.claude/`, `.agents/`, `.windsurf/`, `.cursor/`) are regenerated by `install.sh`
  and MAY be gitignored or committed — see `.gitignore`.

## Interception pipeline priority order

When adding new intercept features, respect this priority (lower runs first):

1. Access control (CIDR allowlist) — connection-level
2. Block list (priority 5)
3. Rewrites
4. Mocks
5. Breakpoints
6. Throttle

## Plugin system

WASM plugins via `wasmtime` with fuel metering. See `references/plugin-workflow.md`
and `docs/PLUGINS.md`, `docs/PLUGIN_DEVELOPMENT.md`, `docs/PLUGIN_API.md`,
`docs/PLUGIN_SECURITY.md`. Guest SDK lives in `crates/madhyamas-plugin-sdk/`.
